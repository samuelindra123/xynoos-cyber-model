# TASK 006-D1 — Objective A v3 Dataset and Baseline

**Status:** reproducible authored-synthetic software control with an unchanged-weight baseline. It is not an Objective B corpus, cybersecurity evidence, or a statistically powered learning benchmark.

## Identity and construction

The corpus is generated by `tools/task006_objective_a_v3.py` and checked by the separate Python standard-library implementation in `tools/task006_objective_a_v3_audit.py`. It contains no external data. The two implementations independently recompute the tokenizer and semantic split assignment; they were authored in this engineering session, so this cross-implementation check is not independent human review.

Each task-input combination is unique across the corpus. Prompt templates are reserved by split: indices 0–3 for train, 4–5 for validation, and 6–7 for test. The audit finds zero normalized exact cross-split duplicates, zero task-input overlap, zero template overlap, and zero cross-split character-trigram pairs at the fixed 0.82 threshold. Maximum cross-split trigram Jaccard is 0.461538. These checks reduce known template leakage; they do not establish semantic independence or broad generalization.

Payloads contain 5–14 BPE tokens and each example fits one padded 16-position row. The answer ends align to BPE boundaries in all 60 rows. Ten answer starts fall inside a merged BPE token, so the answer-bearing metric includes some prompt bytes for those rows; it is not strict answer-only loss. The audit counts 35/28/27 answer-bearing target positions for train/validation/test.

All reports have finite loss and the same model-state digest. The public test was read for the explicitly tagged initial baseline. Training admission rejects test data, and the test metric is not used for learning-rate selection. The 91.38-second local debug test duration is a software-test observation, not a provider throughput estimate.

The v3 unchanged-weight baseline did not train the model. Its `[2, 16]` evaluation batches differ from the trainer's `[1, 32]` input contract. A trainer-compatible stream now emits one padded `[1, 32]` batch per training document, preserving document boundaries and masking padding; the data regression confirms 24 batches, 197 supervised targets, zero dropped tails, and deterministic order. The focused native integration control then completed two bounded optimizer updates from the train split, evaluated validation only, confirmed finite loss and a parameter change, wrote two validation events and a checkpoint, and observed no test access. The focused debug test passed at source revision `74831336ae081ee65b3f18071208ed812bd73f66` in 17.27 seconds. This is software-path verification only: two updates do not show that the corpus or schedule can establish learning, generalization, or scientific sufficiency, and this was not a TASK 006-D training experiment.

## Limits and admission

This dataset is a narrow three-family synthetic compositional control. It contains only 18 examples in each held-out split, exposes its public test in Git, and has one authored source and one creation date. Source-based or time-based generalization cannot be measured. The task inventory is small enough that memorization remains plausible even though operands and templates do not cross split boundaries. There is no human quality review. It cannot establish broad reasoning or cybersecurity competence.

Use v3 only for deterministic Objective A software checks until a human reviewer assesses task validity and held-out quality. Do not treat this baseline as proof that any update schedule is sufficient. Objective B still requires a separate licensed, provenance-reviewed corpus; no external data was acquired.
