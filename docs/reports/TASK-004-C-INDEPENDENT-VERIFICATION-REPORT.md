## C. Byte tokenizer

`TokenId` is `u32`; byte IDs are the corresponding values `0..=255`. The registry is fixed at BOS 256, EOS 257, PAD 258, and DOC_SEP 259, giving a 260-entry base vocabulary. Exhaustive byte tests round-trip all 256 values, reversed and generated byte sequences, empty input, NUL, invalid UTF-8 bytes, CRLF, tabs, Unicode UTF-8, and literal marker spellings. Byte APIs preserve marker text as ordinary bytes; only `Boundaries` inserts BOS/EOS. Strict text decoding returns `InvalidUtf8` for invalid bytes.

Decode validates IDs and the document grammar: optional BOS only at position zero and EOS only at the end; PAD and DOC_SEP are rejected. `Omit` and spelling-render modes are explicit. Empty byte input encodes and decodes to empty; explicit BOS+EOS around empty content are valid under the selected special decode policy. Output length, token count, checked size arithmetic, capacity accounting, and fallible vector reservation are enforced. Rendered marker spellings are display output and can collide with literal marker text, as documented.

## D. Native BPE

`BpeTrainer` counts adjacent pairs within each document, including overlapping windows, and isolates document boundaries. It stops when no pair reaches frequency two, selects maximum frequency with lexicographic operand-ID tie-break, assigns contiguous IDs from 260, and replaces left-to-right without overlap. Failed `push_document` invalidates the trainer; `finish` returns either a complete model or an error. Encoding repeatedly selects the minimum available merge rank and applies that pair left-to-right. Decoding uses validated flat byte expansions.

Independent calculations encoded in `crates/xynoos-tokenizer/tests/task004c_independent.rs` verify: an `ab`/`ba` frequency tie chooses `(97,98)`; `aaa` with overlapping `aa` occurrences becomes `[260,97]`; six `a` bytes learn `aa` then `(260,260)` and encode as `[261,260]`; separate one-byte documents cannot form `ab`; and a model whose rank 0 is `bc` and rank 1 is `ab` encodes `abc` as `[97,260]`, proving rank-first selection instead of leftmost-pair selection. Checked counter overflow has a direct unit check. Work charging includes pair-table initialization, document visits, overlapping counts, selection, replacements, expansion copies, lookup comparisons, and encoding replacement scans.

Trainer and loader cap at 512 merges / 772 total vocabulary entries. The 65,536 format namespace is not the supported production table size. Training corpus bytes, document count, expansion, vocabulary, owned capacity, and work budgets are capped. The algorithm-only BPE API accepts arbitrary caller-provided bytes; governance is applied separately by `Dataset::fit_bpe`.

## E. Tokenizer artifact

The version-1 artifact uses the exact `XYNOOS-TOKENIZER\t1` header, algorithm and vocabulary lines, ordered special registry, rank-ordered merge rows, lowercase hexadecimal expansion, and final LF. SHA-256 covers all preceding lines including their LF. Loader checks checksum before semantic parse, rejects noncanonical integer/hex spelling, CRLF, missing final LF, trailing content, unsupported version/algorithm, incorrect registry, inconsistent vocabulary, invalid rank/ID/forward reference, duplicate pair, special operands, and incorrect flat expansion. Aliases are allowed when different valid earlier-only merge trees yield identical bytes; the auditor-authored artifact test proves this and flat decode.

Existing malformed-artifact tests recompute a valid checksum for structural mutations, so semantic rejection is separately exercised from checksum failure. `read` bounds staging and artifact bytes, uses fallible growth, and only returns a model after complete parse. SHA-256 detects accidental changes; it does not establish artifact origin or authenticity.

## F. Dataset governance and parser

The source schema requires stable reference/revision, acquisition and review dates, source checksum, license and terms metadata, explicit approved training permission, redistribution permission and conditions, transformations, domain, maintainer, and approved review status. The document schema requires identity, source/revision binding, normalized relative payload path, exact byte length and SHA-256, UTF-8 encoding, sorted unique domain labels, split, cleaning and transformation metadata, tokenizer compatibility, and content-digest duplicate group. Struct deserialization rejects duplicate and unknown fields. Canonical reserialization rejects noncanonical ordering, whitespace, escaping, JSON spelling, and LF violations. Required references, versions, enums, identifiers, transformation history, provenance, source linkage, and payload bounds are checked.

Dataset identity is independently derived using `XYNOOS-DATASET-V1\0`, big-endian source/document byte lengths, and exact canonical JSONL bytes. The sidecar binds both JSONL checksums; each row binds its payload checksum. Diagnostics are typed enums and retain only I/O kinds; JSON and UTF-8 errors do not echo untrusted text or paths. The parser and allocator have implementation-internal scratch outside the explicitly measured capacity counters, as documented. Valid metadata does not prove legal permission, privacy completeness, or source-authenticity.

## G. Filesystem security

Path validation rejects absolute, drive-like, traversal, empty, malformed, non-ASCII, reserved-device, and nonnormalized components. Each metadata/payload path component is checked with `symlink_metadata`; intermediate components must be directories, final components regular files, and symlink payloads, intermediate symlinks, and metadata symlinks fail. Missing files and nonregular files fail closed. Payload open verifies declared and actual length, reads exact content, probes for extra bytes, verifies SHA-256, then validates UTF-8 and forbidden BOM/NUL before returning a `Document` or token batch. The reader stores a sticky terminal error; no sample is returned for a rejected payload.

Synthetic tests cover final, intermediate-directory, and control-file symlinks, missing files, malformed paths, invalid UTF-8, length and checksum mismatches, nonregular entries, and payload mutation after validation. No sensitive host files were accessed.

The guarantee assumes caller-controlled root and ancestor directories and a stable tree during use. Metadata checks and subsequent opens are subject to TOCTOU races under concurrent hostile mutation. Hard links, mount configuration, and a hostile root owner are outside the guarantee. The implementation rejects a symlink root before canonicalizing it; it does not attempt to defend against privileged filesystem remounts or concurrent mutation.

## H. Splitting and fit provenance

Split assignment hashes ASCII `1`, NUL, seed, NUL, and lowercase content SHA-256; the first eight digest bytes are interpreted big-endian and compared using exact integer 80/90 percent thresholds. Content SHA-256 is the duplicate group key, independent of caller labels, so repeated content across source IDs receives one assignment. Cross-split duplicate content and duplicate IDs are rejected. Document iteration follows the exact validated JSONL order, not filesystem enumeration; ordered Train-row hashing preserves that order.

Only `Split::Train` is accepted by `Dataset::fit_bpe`; it streams integrity-checked Train documents, then records dataset identity, ordered Train manifest digest, Train count, requested merges, and artifact digest. `FittedTokenizer` fields are private and `fitted_batches` requires the dataset-bound handle. `verify_fit` checks canonical fit bytes and dataset/artifact digests, algorithm, and compatibility. This is binding and consistency validation, not historical authenticity of an externally supplied fit producer. The public algorithm-level trainer remains intentionally separate from governed fitting.

## I. Streaming and batches

The line reader reuses a bounded buffer, rejects overlong or unterminated final records, distinguishes clean EOF from I/O errors, and retains only bounded metadata indices during open. Readers process rows in manifest order, yield one integrity-checked document at a time, terminate on error, and release owned buffers when dropped. Batch streams tokenize one current document and assemble one batch; default windows never cross a document. The API supports explicit BOS/EOS, stride `1..=L`, drop or PAD tails, actual-size final batches, and optional fixed-size batch padding. Inputs/targets are integer `u32`; target shift is exact; validity and loss masks use byte values and PAD is excluded from loss.

Auditor-authored batch verification independently reconstructs a 96-position padded row from the first Train payload: the `N-1` input bytes, one-position-shifted `N-1` targets, then PAD through all remaining positions; both masks are `1` for the `N-1` supervised pairs and `0` for all padded positions. The stream then yields separate one-row batches for the remaining documents. Existing tests also exercise partial batches, all pad-tail IDs/masks, stride one, drop-tail counts, configuration rejection, token-budget failure, and document-control validation. The crate defines no attention mask.

## J. Resource and work accounting

The supported BPE vocabulary is 772 including specials.

Small caller limits exercise input, output, retained-buffer, work, artifact, document, metadata, batch-size, sequence, and positions failures. Checked add/multiply/count operations are used on resource dimensions; vector allocation uses `try_reserve` in project-owned paths. Capacity reports count vector capacities and nested owned strings/lists for their named budgets. Serde parser state/string escape scratch, allocator rounding/reallocation internals, caller-owned inputs/results, OS page cache, stacks, and unrelated process memory are excluded. These are application allocation ceilings, not RSS guarantees. The trainer's dense count matrix and touched indices have bounded size and their initialization and iteration are charged; no identified algorithmic traversal bypasses the stated BPE work ceilings.

## R. Remaining limitations

- Rights, source checksum provenance, maintainer identity, and external fit history are caller-supplied claims; hashes bind bytes but do not authenticate people or legal authority.
- The privacy screen is not a guarantee. Near-duplicate, translated, normalized, semantic, and source-group leakage are not solved by exact content-hash grouping.
- Filesystem verification assumes a trusted stable root. Concurrent mutation, TOCTOU races, hard links, mount changes, and trusted ancestor compromise are outside the guarantee.
- Parser-internal scratch and process RSS are not fully accounted. The implementation promises bounded measured application-owned vector capacity within named budgets, not a process-memory maximum.
- The dense deterministic BPE trainer is deliberately reference-scale, bounded to 512 merges and 128 KiB corpus. The small fixture cannot establish broad-language or production efficiency.
- SHA-256 integrity is not a signature, provenance proof, or authenticity mechanism.
